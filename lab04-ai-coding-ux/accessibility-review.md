# Accessibility & Usability Review - Lab 04

การตรวจสอบความพร้อมด้านการเข้าถึง (Accessibility - WCAG 2.1 AA) และความสะดวกในการใช้งาน (Usability) ของ UI Mockup ระบบ Inventory Management 

**กลุ่มเป้าหมายผู้ออกแบบอ้างอิง:** ป้าพร (อายุ 50 ปี, พนักงานบัญชีและคลังอู่ซ่อมรถ, ทักษะดิจิทัล 2/5, สายตายาว, หน้าจอ PC 19 นิ้ว ความละเอียด 1366x768)

---

## 1. ตารางตรวจสอบ Accessibility Checklist (WCAG 2.1 Level AA)

| รายการตรวจ (Checklist Item) | เกณฑ์อ้างอิง | ผ่าน / ไม่ผ่าน | สิ่งที่ตรวจพบและแนวทางปรับปรุงใน Mockup |
| :--- | :--- | :---: | :--- |
| **1. Contrast ข้อความหลักบนพื้นขาว** | WCAG 1.4.3 (Contrast Minimum ≥ 4.5:1) | **ผ่าน ✅** | ใช้สีข้อความหลัก `#111827` (Very Dark Gray) บนพื้นหลังสีขาว `#FFFFFF` ซึ่งให้อัตราส่วน Contrast สูงถึง **15.4:1** อ่านง่าย ชัดเจน ไม่เพ่งสายตา |
| **2. Contrast ปุ่ม Primary** | WCAG 1.4.3 & 1.4.11 (Contrast ≥ 4.5:1 สำหรับปุ่ม) | **ผ่าน ✅** | ปุ่ม "เข้าสู่ระบบ" และ "บันทึกข้อมูล" ใช้สีพื้นหลัง Primary Blue `#1E40AF` ร่วมกับตัวอักษรสีขาว `#FFFFFF` ให้อัตราส่วน Contrast อยู่ที่ **8.3:1** ผ่านเกณฑ์อย่างสมบูรณ์ |
| **3. Label ประจำช่องกรอกข้อมูล** | WCAG 3.3.2 (Labels or Instructions) | **ผ่าน ✅** | ทุกช่องกรอก (Input Field) มี Visible Label วางไว้ด้านบนช่องอย่างถาวร ไม่ใช้เพียง Placeholder จางๆ ภายในช่อง ป้องกันปัญหาเมื่อพิมพ์แล้วจำไม่ได้ว่าคือช่องอะไร |
| **4. สัญลักษณ์ช่องที่บังคับกรอก (Required Fields)** | Usability & Form Validation | **ผ่าน ✅** | ช่องที่จำเป็นต้องกรอกมีสัญลักษณ์ดอกจันสีแดง `*` (พร้อมระบุคำอธิบายด้านบนว่าเครื่องหมาย `*` คือช่องที่จำเป็น) เช่น ชื่อสินค้า*, ชนิดสินค้า*, จำนวน* |
| **5. การแสดง Error State ที่ไม่พึ่งพาสีอย่างเดียว** | WCAG 1.4.1 (Use of Color) | **ผ่าน ✅** | กล่องและข้อความแจ้งเตือนความผิดพลาด ใช้ทั้งสัญลักษณ์ไอคอนตกใจ `[!]`, กรอบเน้นเส้นหนา, และข้อความอธิบายวิธีแก้ที่ชัดเจน เช่น `! ข้อผิดพลาด: กรุณากรอกเป็นตัวเลขจำนวนเต็มบวก` ไม่ใช้เพียงการเปลี่ยนกรอบเป็นสีแดงอย่างเดียว |
| **6. ลำดับการกด Tab (Keyboard Focus Order)** | WCAG 2.4.3 (Focus Order) | **ผ่าน ✅** | กำหนด Tab Sequence เรียงลำดับจากบนลงล่าง และซ้ายไปขวาอย่างเป็นธรรมชาติ (ชนิดสินค้า -> ชื่อ -> จำนวน -> ราคา -> ยกเลิก -> บันทึก) พร้อมแสดง Focus Ring สีน้ำเงินเข้มรอบช่องที่กำลังเลือก |
| **7. ข้อความบนปุ่มระบุหน้าที่ชัดเจน (Descriptive Buttons)** | WCAG 2.4.6 (Headings and Labels) | **ผ่าน ✅** | หลีกเลี่ยงคำคลุมเครือ เช่น "OK", "Submit", หรือ "Cancel" โดยใช้คำกริยาภาษาไทยที่ชัดเจน เช่น "เข้าสู่ระบบ (Login)", "บันทึกข้อมูล", "ยกเลิกการทำรายการ", "เติมของสต็อก" |

## 2. จุดที่ AI มักพลาดในงาน UI และการแก้ไขด้วยตนเอง (AI UI Flaws & Human Corrections)

จากการใช้ AI ช่วยร่าง Wireframe ใน `assets/wireframe-ai.md` พบข้อบกพร่องด้าน Usability และ Accessibility ซึ่งได้รับการตรวจสอบและปรับปรุงแก้ไขในขั้นตอนทำ Mockup ดังนี้:

### จุดที่ 1: การใช้ Placeholder สีเทาจางแทน Visible Label ถาวร
* **ข้อผิดพลาดของ AI:** ในการร่างครั้งแรก AI สร้างฟอร์มที่มีเฉพาะข้อความลางๆ (Placeholder Text) อยู่ภายในกล่องกรอก เช่น `[ กรอกชื่อสินค้า... ]` โดยไม่มีป้ายกำกับด้านบน
* **ผลกระทบต่อผู้ใช้:** ป้าพรที่มีปัญหาสายตายาวจะมองไม่เห็นตัวหนังสือสีเทา และเมื่อเริ่มพิมพ์ข้อความ Placeholder จะหายไป ทำให้สับสนว่ากำลังกรอกข้อมูลช่องใด
* **สิ่งที่แก้ไขเองใน Mockup:** เพิ่ม Label ตัวหนาสีเข้ม `#111827` ขนาด 16px อยู่เหนือช่องกรอกทุกช่องอย่างถาวร พร้อมระบุหน่วยนับกำกับชัดเจน เช่น `3. จำนวนสต็อกเริ่มต้น (ชิ้น) *`

### จุดที่ 2: การวางปุ่มกระทำหลัก (Primary) ชิดกับปุ่มยกเลิก (Secondary) และใช้สีที่ Contrast ต่ำ
* **ข้อผิดพลาดของ AI:** AI วางปุ่ม "บันทึก" และ "ยกเลิก" ไว้ติดกันตรงมุมขวาล่าง และใช้สีเทาอ่อน `#D1D5DB` สำหรับปุ่มยกเลิกโดยมีตัวหนังสือสีขาว ซึ่ง Contrast ต่ำเพียง `1.5:1` (ไม่ผ่านเกณฑ์)
* **ผลกระทบต่อผู้ใช้:** ผู้สูงอายุที่ใช้เมาส์ไม่คล่องมีโอกาสคลิกพลาดไปโดนปุ่มยกเลิก ข้อมูลที่กรอกมาทั้งหมดจะสูญหายทันที
* **สิ่งที่แก้ไขเองใน Mockup:**
  1. แยกตำแหน่งและระยะห่างของปุ่มให้ห่างกันอย่างน้อย 24px (ปุ่มยกเลิกอยู่ซ้าย/ปุ่มบันทึกอยู่ขวาสุด)
  2. เปลี่ยนสีปุ่มยกเลิกเป็นกรอบเส้น (Outline Button) สีเทาเข้ม `#4B5563` บนพื้นขาว ซึ่งให้ Contrast สูงถึง `7.4:1`
  3. เพิ่มขนาดพื้นที่กด (Target Size) ของปุ่มบันทึกให้มีขนาดอย่างน้อย 48x48 px ตามข้อกำหนด WCAG 2.5.5

### จุดที่ 3: ข้อความแจ้งเตือนข้อผิดพลาด (Validation Error) คลุมเครือและใช้สีแดงเพียงอย่างเดียว
* **ข้อผิดพลาดของ AI:** AI ออกแบบให้เมื่อกรอกสต็อกผิด ช่องกรอกจะเปลี่ยนเป็นเส้นขอบสีแดงพร้อมคำว่า "Invalid input"
* **ผลกระทบต่อผู้ใช้:** ป้าพรอ่านภาษาอังกฤษไม่ออก และไม่เข้าใจว่ากรอกผิดอย่างไร ทำให้เกิดความวิตกกังวลและทำงานต่อไม่ได้
* **สิ่งที่แก้ไขเองใน Mockup:** 
  1. เปลี่ยนข้อความเป็นภาษาไทยที่ระบุคำแนะนำวิธีแก้ไขชัดเจน: `! กรุณากรอกจำนวนเป็นตัวเลขจำนวนเต็มบวก (เช่น 1, 5, 10)`
  2. เพิ่มไอคอนเครื่องหมายตกใจ `[! / ⚠️]` เพื่อให้ผู้ที่มีภาวะตาบอดสีสามารถรับรู้ได้ทันทีว่าเกิดข้อผิดพลาด

### จุดที่ 4: การละเลยความแตกต่างระหว่าง "สินค้าจับต้องได้" กับ "ไฟล์ดิจิทัล"
* **ข้อผิดพลาดของ AI:** AI มองระบบคลังเป็นสินค้าแบบเดียว โดยทุกสินค้าต้องกรอก "จำนวนสต็อก" และ "คลังจัดเก็บ"
* **ผลกระทบต่อระบบ:** สินค้าที่เป็นไฟล์คู่มือ PDF หรือไฟล์โค้ดดิจิทัลไม่มียอดสต็อกที่จับต้องได้ หากให้กรอกสต็อกจะทำให้เกิดความสับสนและยอดบัญชีคลาดเคลื่อน
* **สิ่งที่แก้ไขเองใน Mockup:**
  1. เพิ่มตัวเลือกแบบ Radio Button โตๆ ในขั้นตอนแรกสุดของหน้า Add Product:
     - `(*) สินค้าจับต้องได้ / อะไหล่จริง (มีสต็อกจริง ต้องตรวจนับ)`
     - `( ) สินค้าดิจิทัล / ไฟล์คู่มือ (ไม่มีสต็อก ส่งลิงก์โหลดหลังชำระเงิน)`
  2. เมื่อเลือก "สินค้าดิจิทัล" ช่อง "จำนวนสต็อกเริ่มต้น" จะถูก Disable อัตโนมัติและแสดงป้ายกำกับว่า `[ ไม่ต้องระบุจำนวน - สินค้าดิจิทัล ]` เพื่อป้องกันความสับสน
